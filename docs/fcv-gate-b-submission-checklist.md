# FCV Gate B Submission and Follow-up Checklist

Use this as the canonical checklist for the initial submission and FCV response loop.

## 1) Pre-Submission

- [ ] Gate B request narrative finalized (`docs/fcv-gate-b-pilot-request.md`)
- [ ] Legal/compliance pages checked (`/integrations`, `/pricing`, `/terms`, `/privacy`, `/data-sources`)
- [ ] Artifact pack complete (`docs/fcv-gate-b-artifact-pack.md`)
- [ ] Signed security and attestation docs attached
- [ ] Pilot tester roster and duration attached
- [ ] No-public-marketing statement included

## 2) Initial Submission

- [ ] Send one structured email with all links and attachments
- [ ] Include explicit statement: Gate A not yet met; requesting Gate B pilot
- [ ] Include support/security points of contact
- [ ] Archive sent message and attachments in shared folder

## 3) FCV Follow-up Tracker

Track each FCV request as one row:

| Date | FCV Request | Owner | Due | Status | Evidence Delta Sent |
|------|-------------|-------|-----|--------|---------------------|
| YYYY-MM-DD | Example: Move disclaimer above fold on pricing | Name | YYYY-MM-DD | Open | Replaced `fcv-gateb-pricing-page.png` |

Follow-up rules:
- Respond with deltas only (updated screenshot/doc/video section), not a full resend unless requested.
- Prioritize copy/placement fixes before architecture improvements when FCV blocks on compliance text.
- Keep one source of truth for current package version.

## 4) Approval Gate

Mark complete when all are true:

- [ ] FCV confirms pilot allowlist approval
- [ ] FCV constraints and conditions documented
- [ ] Pilot start date confirmed
- [ ] Any pre-start conditions satisfied

## 5) Post-Approval Hygiene

- [ ] Lock approved disclaimer copy to prevent drift
- [ ] Save “approved package” snapshot in dated folder
- [ ] Start pilot evidence log for Gate A bridge reuse
